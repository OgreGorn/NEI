## Задание 2. Анализ синтаксической конструкции c = a++b

Конструкция была проверена в средах C++ (файл `check2.cpp`) и Python (файл `check2.py`) для анализа того, как трансляторы делят исходный текст на последовательности отдельных элементов (токенов).

* **Последовательность токенов в C++:** `[int] [a] [=] [1] [,] [b] [=] [2] [;] [int] [c] [=] [a] [++] [b] [;]`
* **Последовательность токенов в Python:** `[a] [=] [1] [\n] [b] [=] [2] [\n] [c] [=] [a] [+] [+] [b] [\n]`

### Ход тестирования и результаты:

1. **Тестирование выражения в C++:**
При попытке скомпилировать файл компилятор g++ выдал ошибку. Лексический анализатор C++ объединяет идущие подряд символы в максимально длинную допустимую операцию согласно правилу максимального поглощения. В данном случае два плюса были восприняты как единый оператор постфиксного инкремента `++`. Выражение приняло неверный вид `c = (a++) b;`, где между инкрементом и переменной 'b' отсутствует знак бинарной операции, что недопустимо грамматикой.

![Ошибка в check2.cpp](screen/p4.png)

2. **Тестирование выражения в Python:**
При запуске скрипта программа успешно выполнилась и вывела результат `3`. Поскольку в языке Python операции инкремента `++` не существует, анализатор воспринял два знака плюс как два отдельных унарных плюса перед переменной. Выражение было успешно обработано как стандартное сложение: `c = a + (+b)`.

![Работа check2.py](screen/p5.png)

## Задание 3. Анализ синтаксической конструкции int c = a+++b;

Конструкция с тремя знаками плюс подряд была проверена в среде C++ с помощью запуска исполняемого файла `check3.cpp`.

* **Последовательность токенов:** `[int] [a] [=] [,] [b] [=] [;] [int] [c] [=] [a] [++] [+] [b] [;]`

### Ход тестирования и результаты:

Программа была успешно скомпилирована и запущена в консоли Far Manager. Код отработал корректно, выдав итоговые значения переменных: `a = 2`, `b = 2`, `c = 3`.

![Работа check3.cpp](screen/p6.png)

### Объяснение результатов:
Анализатор сгруппировал первые два плюса в оператор постфиксного инкремента `++`, а третий плюс определил как оператор бинарного сложения. В итоге получилось выражение `c = (a++) + b;`. 
Так как инкремент является постфиксным, для сложения используется текущее значение переменной 'a' (равное 1). Таким образом, `c = 1 + 2 = 3`. Только после завершения вычисления этого выражения значение переменной 'a' увеличилось на единицу и стало равно 2. Переменная 'b' своего значения не изменила.

Влияние пробелов: Расстановка пробелов напрямую влияет на разделение текста на элементы. Если записать выражение как `a + ++b`, оно будет обработано по другой логике (сложение и префиксный инкремент). В этом случае переменная 'b' сначала увеличится до 3, а затем прибавится к 'a' (1), что даст результат `c = 4`.

## Задание 4. Анализ круглых () и квадратных [] скобок в роли операторов

Различные роли скобок в зависимости от контекста программы были проверены и продемонстрированы в коде `check4.cpp`.

### Ход тестирования и результаты:

Проверочный файл был успешно скомпилирован и запущен. Программа вывела результаты работы скобок в консоль.

![Работа check4.cpp](screen/p7.png)

### Синтаксический разбор ролей скобок:
* **Квадратные скобки `[]`:** Выступают в роли оператора, когда используются для доступа к элементу массива по его индексу (например, `arr`). Не являются оператором, когда служат частью синтаксиса при объявлении статического массива и указании его размерности (`int arr[] = {10, 20, 30};`).
* **Круглые скобки `()`:** Выступают в роли оператора при вызове функций (`my_func()`) или при явном преобразовании типов данных (`(int)pi`). Не являются оператором, когда используются исключительно для изменения стандартного приоритета математических действий в сложных выражениях (например, `(5 + 3) * 2`).

## Задание 6. Анализ синтаксической верности комментариев в C++

Различные варианты записи однострочных и многострочных комментариев были проверены путём компиляции файла `check6.cpp`.

### Ход тестирования и результаты:

При попытке скомпилировать файл компилятор g++ прервал трансляцию и выдал лог синтаксических ошибок из-за неверного использования вложенности маркеров.

![Ошибки в check6.cpp](screen/p9.png)

### Разбор примеров со слайда:
1. `cout << "Hello /* комментарий */ world";` — **Ошибок нет.** Знаки находятся внутри двойных кавычек строкового литерала. Они воспринимаются как обычный текст, а не как разметка комментария.
2. `// /* \n Это комментарий \n */` — **Синтаксическая ошибка.** Знак `//` комментирует всю первую строку вместе с открывающим маркером `/*`. Текст на новой строке компилятор пытается обработать как исполняемый код, что приводит к сбою.
3. `/* текст /* комментарий */ */` — **Синтаксическая ошибка.** В языке C++ многострочные комментарии не могут быть вложенными. Первый встреченный закрывающий маркер `*/` завершает весь комментарий, а конечный хвост `*/` остаётся лишним в коде.
4. `// текст /* комментарий */` — **Ошибок нет.** Знак `//` в начале строки заставляет компилятор полностью проигнорировать всё содержимое до конца текущей строки.
5. `/* текст // текст */ \n */` — **Синтаксическая ошибка.** Знак `//` внутри многострочного блока игнорируется. Первый маркер `*/` завершает блочный комментарий, а одинокий маркер `*/` на новой строке вызывает ошибку.

## Задание 7. Синтаксические правила инструкций циклов в стандарте C++

Формальные правила грамматики для циклов были проверены на этапе компиляции в файле `check7.cpp`.

### Ход тестирования и результаты:

Был скомпилирован файл, содержащий все четыре регламентированных стандартом типа циклов. Сборка прошла успешно, синтаксических ошибок в структурах не обнаружено.

![Компиляция check7.cpp](screen/p10.png)

### Правила грамматики из стандарта C++17:
1. `while ( condition ) statement` — Цикл с предусловием (while). Выполняет инструкцию, пока проверяемое условие истинно.
2. `do statement while ( expression ) ;` — Цикл с постусловием (do-while). Гарантирует как минимум один проход тела цикла до первой проверки условия.
3. `for ( init-statement condition_opt ; expression_opt ) statement` — Традиционный цикл for, содержащий секции инициализации, условия и шага.
4. `for ( for-range-declaration : for-range-initializer ) statement` — Диапазонный цикл (range-based for), предназначенный для последовательного обхода коллекций и массивов.

## Задание 8. Построение абстрактного синтаксического дерева (AST)

Синтаксическая структура выражения `a = -x + y * (z - 1);` была проверена на этапе компиляции в файле `check8.cpp`.

### Ход тестирования и результаты:

Программа была успешно скомпилирована, что подтвердило корректность структуры выражения с точки зрения грамматики языка.

![Компиляция check8.cpp](screen/p11.png)

### Порядок синтаксического разбора выражения:
Синтаксическое дерево строится на основе приоритета операций. Скобки в структуре дерева не отображаются, так как приоритет вычислений задаётся самой иерархией ветвления.

<pre>
                  [ = ]
                 /     \
                a       [ + ]
                       /     \
                     [ - ]    [ * ]
                       |     /     \
                       x    y     [ - ]
                                 /     \
                                z       1
</pre>

### Текстовое описание иерархии дерева (AST) по уровням:

* **Корень дерева (Уровень 0):** Оператор присваивания `[=]`
  * **Левая ветвь (Уровень 1):** Переменная `a` (Идентификатор)
  * **Правая ветвь (Уровень 1):** Оператор бинарного сложения `[+]`
    * **Левый потомок сложения (Уровень 2):** Оператор унарного минуса `[-]`
      * **Потомок унарного минуса (Уровень 3):** Переменная `x` (Идентификатор)
    * **Правый потомок сложения (Уровень 2):** Оператор умножения `[*]`
      * **Левый потомок умножения (Уровень 3):** Переменная `y` (Идентификатор)
      * **Правый потомок умножения (Уровень 3):** Оператор бинарного вычитания `[-]`
        * **Левый потомок вычитания (Уровень 4):** Переменная `z` (Идентификатор)
        * **Правый потомок вычитания (Уровень 4):** Константа `1` (Литерал)

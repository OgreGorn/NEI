Проверил эту строчку на C++ и Python (файлы check2.cpp и check2.py).

Последовательность токенов в C++:
[int] [a] [=] [1] [,] [b] [=] [2] [;] [int] [c] [=] [a] [++] [b] [;]

Последовательность токенов в Python:

Почему такие результаты:
- В C++ код не скомпилировался. Лексер пытается сожрать максимальную длину символов, поэтому слил два плюса в один оператор инкремента (++). Получился бред: c = (a++) b. Из-за того, что между a++ и b нет никакого знака (плюса или минуса), вылетела ошибка.
![Ошибка в check2.cpp](screen/p4.png)
- В Python код сработал и выдал 3. В питоне знака ++ вообще нет, поэтому он разбил это на два отдельных унарных плюса. Вышло простое сложение: c = a + (+b).

## Задание 3. Выражение int c = a+++b;
Написал код в файле check3.cpp, скомпилировал и запустил.

Последовательность токенов:
[int] [a] [=] [1] [,] [b] [=] [2] [;] [int] [c] [=] [a] [++] [+] [b] [;]

Результаты запуска:
Код успешно отработал и вывел в консоль: a=2, b=2, c=3.
![Работа check3.cpp](screen/p6.png)

Почему так вышло:
Компилятор забрал первые два плюса под инкремент (++), а третий плюс стал обычным сложением. Получилось выражение c = (a++) + b. Так как инкремент постфиксный, для сложения берется старое значение "a" (то есть 1). В итоге c = 1 + 2 = 3. А уже потом переменная "a" увеличилась в памяти на единицу и стала равна 2.

Влияют ли пробелы: Да, влияют. Если поставить пробелы вот так: a + ++b, то лексер разобьет код по-другому (сложение и префиксный инкремент b). Тогда сначала b увеличится до 3, а потом прибавится к a (1). Результат c станет равен 4.

## Задание 4. Скобки () и []
Написал простой пример check4.cpp, чтобы посмотреть, как ведут себя скобки.
![Работа check4.cpp](screen/p7.png)

Разбор:
- Квадратные скобки []: работают как оператор, когда мы берем элемент массива по индексу (например, arr[1]). Но когда мы просто создаем массив (int arr[] = ...), скобки — это не оператор, а часть синтаксиса для выделения памяти под массив.
- Круглые скобки (): работают как оператор, когда мы вызываем функцию (my_func()) или когда принудительно меняем тип данных ((int)pi). Но если мы пишем скобки в математике, чтобы поменять приоритет действий (например, (5 + 3) * 2), то это не оператор, а просто группировка.

## Задание 5. Разбор строки на Python
Код из check5.py: print(*map(sum, zip(*[map(int, input().split()) for i in (1, 2, 3)])))
Запустил, ввел три строчки чисел, программа выдала результат 12 15 18.
![Работа check5.py](screen/p8.png)

Разбор строки:
- Ключевые слова: for, in
- Литералы: 1, 2, 3
- Операторы: * (распаковка списков)
- Переменные: i (счетчик в цикле)
- Функции: print, map, sum, zip, int, input, split

Как это вообще работает:
Программа три раза просит ввести строку чисел. Каждую строку она бьет по пробелам через split() и делает из них цифры через map(int). На выходе получается матрица из трех строк чисел. Функция zip(*...) переворачивает эту матрицу — собирает в группы все первые элементы, все вторые и все третьи (по столбцам). Внешний map(sum) считает сумму в каждом столбце, а print(*...) выводит результат в консоль. По сути, это просто поэлементное сложение трех векторов.

## Задание 6. Комментарии в C++
Написал все примеры в файле check6.cpp и попробовал скомпилировать. g++ выдал пачку ошибок.
![Ошибки в check6.cpp](screen/p9.png)

Разбор примеров:
1. cout << "Hello /* комментарий */ world"; -> Все ок. Кавычки превращают все внутри в обычный текст, компилятор не видит тут комментарий.
2. // /* \n Это комментарий \n */ -> Ошибка. Первая строчка полностью закомментировалась из-за //, а открывающий знак /* пропал. На новой строчке текст "Это комментарий" компилятор посчитал за код и выдал ошибку.
3. /* текст /* комментарий */ */ -> Ошибка. В C++ нельзя делать вложенные блочные комментарии. Первый же знак */ закрывает весь комментарий, а последний хвост */ остается лишним в коде.
4. // текст /* комментарий */ -> Все ок. Знак // в начале строки заставляет компилятор заигнорить абсолютно все символы до конца строки.
5. /* текст // текст */ \n */ -> Ошибка. Знак // внутри блока ни на что не влияет. Первый маркер */ закрывает блок, а одинокий */ на новой строчке ломает компиляцию.

## Задание 7. Правила циклов в стандарте C++
В стандарте C++17 прописано ровно 4 правила для циклов (раздел iteration-statement). Проверил их в файле check7.cpp.
![Компиляция check7.cpp](screen/p10.png)

Правила простыми словами:
1. while ( condition ) statement -> Обычный цикл с предусловием while. Делает тело цикла, пока условие в скобках верно.
2. do statement while ( expression ) ; -> Цикл do-while с постусловием. Сначала делает действие, а потом проверяет условие.
3. for ( init-statement condition_opt ; expression_opt ) statement -> Классический цикл for со счетчиком, условием и шагом.
4. for ( for-range-declaration : for-range-initializer ) statement -> Цикл range-based for (для обхода массивов и коллекций).

## Задание 3. Выражение int c = a+++b;

Написал проверочный код в файле `check3.cpp`, скомпилировал и запустил его в консоли Far Manager.

* **Последовательность токенов:** `[int] [a] [=] [1] [,] [b] [=] [2] [;] [int] [c] [=] [a] [++] [+] [b] [;]`

### Ход тестирования:

Запустил скомпилированную программу. Код успешно отработал без синтаксических ошибок и вывел результаты расчёта переменных.

![Работа check3.cpp](screen/p6.png)

### Пояснение результатов:
Компилятор забрал первые два плюса под инкремент `++`, а третий плюс стал обычным сложением. Получилось выражение `c = (a++) + b;`. Так как инкремент постфиксный, для сложения берется старое значение переменной 'a' (то есть 1). В итоге `c = 1 + 2 = 3`. А уже после этого переменная 'a' увеличилась в памяти на единицу и стала равна 2. Переменная 'b' осталась прежней (2).

Влияют ли пробелы на разбор: Да, влияют. Если поставить пробелы вот так: `a + ++b`, то лексер разобьет код по-другому (выйдет сложение и префиксный инкремент переменной 'b'). Тогда сначала 'b' увеличится до 3, а потом прибавится к 'a' (1). Результат 'c' в таком случае стал бы равен 4.

## Задание 4. Скобки () и []

Написал простой пример `check4.cpp`, чтобы на практике посмотреть, как ведут себя круглые и квадратные скобки.

### Ход тестирования:

Успешно скомпилировал файл и запустил его. Программа вывела результаты работы скобок-операторов на экран.

![Работа check4.cpp](screen/p7.png)

### Разбор скобок:
* **Квадратные скобки `[]`:** Работают как оператор, когда мы берем элемент массива по индексу (например, `arr[1]`). Но когда мы просто создаем статический массив (`int arr[] = ...`), скобки — это не оператор, а часть синтаксиса для выделения памяти.
* **Круглые скобки `()`:** Работают как оператор, когда мы вызываем функцию (`my_func()`) или когда принудительно меняем тип данных в стиле C (`(int)pi`). Но если мы пишем скобки в математике, чтобы просто поменять приоритет действий (например, `(5 + 3) * 2`), то это не оператор, а средство группировки.

## Задание 5. Разбор строки на Python

Код из файла `check5.py`: `print(*map(sum, zip(*[map(int, input().split()) for i in (1, 2, 3)])))`

### Ход тестирования:

Запустил скрипт, ввел три строчки чисел через пробел. Программа успешно посчитала данные и выдала результат.

![Работа check5.py](screen/p8.png)

### Состав токенов в строке:
* **Ключевые слова:** `for`, `in`
* **Литералы:** `1`, `2`, `3`
* **Операторы:** `*` (распаковка списков)
* **Переменные:** `i` (счетчик в цикле)
* **Функции и методы:** `print`, `map`, `sum`, `zip`, `int`, `input`, `split`

### Как это вообще работает:
Программа три раза просит ввести строку чисел. Каждую строку она бьет по пробелам через метод `split()` и делает из них цифры через `map(int)`. На выходе получается матрица из трех строк чисел. Функция `zip(*...)` переворачивает эту матрицу — собирает в группы все первые элементы, все вторые и все третьи (то есть по столбцам). Внешний `map(sum)` считает сумму в каждом получившемся столбце, а `print(*...)` выводит результат в консоль. По сути, это просто поэлементное сложение трех векторов.

## Задание 6. Комментарии в C++

Написал все предложенные примеры комментариев в файле `check6.cpp` и попробовал скомпилировать.

### Ход тестирования:

Запустил сборку файла. Компилятор g++ ожидаемо выдал пачку ошибок из-за некорректной вложенности маркеров разметки.

![Ошибки в check6.cpp](screen/p9.png)

### Разбор примеров:
1. `cout << "Hello /* комментарий */ world";` — **Все ок.** Кавычки превращают все внутри в обычный строковый литерал, компилятор не видит тут комментарий и воспринимает как текст.
2. `// /* \n Это комментарий \n */` — **Ошибка.** Первая строчка полностью закомментировалась из-за `//`, а открывающий знак `/*` пропал. На новой строчке текст "Это комментарий" компилятор посчитал за код и выдал синтаксический сбой.
3. `/* текст /* комментарий */ */` — **Ошибка.** В C++ нельзя делать вложенные блочные комментарии. Первый же знак `*/` закроет весь комментарий, а последний хвост `*/` останется лишним в коде.
4. `// текст /* комментарий */` — **Все ок.** Знак `//` в начале строки заставляет компилятор заигнорить абсолютно все символы до конца текущей строки.
5. `/* текст // текст */ \n */` — **Ошибка.** Знак `//` внутри блока ни на что не влияет. Первый маркер `*/` закрывает блок, а одинокий `*/` на новой строчке ломает компиляцию.

![Компиляция check7.cpp](screen/p10.png)

### Правила грамматики простыми словами:
1. `while ( condition ) statement` — Обычный цикл с предусловием while. Выполняет тело цикла, пока условие в скобках верно.
2. `do statement while ( expression ) ;` — Цикл do-while с постусловием. Сначала делает действие, а потом проверяет условие.
3. `for ( init-statement condition_opt ; expression_opt ) statement` — Классический параметрический цикл for со счетчиком, условием и шагом.
4. `for ( for-range-declaration : for-range-initializer ) statement` — Диапазонный цикл range-based for (для удобного обхода массивов и коллекций).

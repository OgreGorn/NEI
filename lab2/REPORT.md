## Задание 3. Анализ синтаксической конструкции int c = a+++b

Конструкция с тремя плюсами подряд проверена в среде C++ с помощью запуска исполняемого файла `check3.cpp`.

* **Последовательность токенов:** `[int] [a] [=] [1] [,] [b] [=] [2] [;] [int] [c] [=] [a] [++] [+] [b] [;]`

### Ход тестирования:

Запустил скомпилированную программу в консоли Far Manager. Код успешно отработал без ошибок, выдав итоговые значения переменных: `a = 2`, `b = 2`, `c = 3`.
![Успешное выполнение check3.exe в консоли](screen/p6.png)

### Пояснение результатов:
По правилу максимального поглощения лексер забрал первые два плюса под токен постфиксного инкремента `++`, а третий плюс стал бинарным сложением: `c = (a++) + b;`. При вычислении сложения используется старое значение переменной 'a' (равное 1), поэтому `c = 1 + 2 = 3`. После этого значение 'a' увеличилось на единицу, став равным 2.

Расстановка пробелов напрямую влияет на токенизацию, так как они служат разделителями. Если переписать код как `a + ++b`, лексер выделит бинарное сложение и префиксный инкремент. В таком случае 'b' сначала увеличится до 3, а результат 'c' станет равен 4.

## Задание 4. Анализ круглых () и квадратных [] скобок в роли операторов

Синтаксические роли скобок были проверены и продемонстрированы в коде программы `check4.cpp`.

### Ход тестирования:

![Успешное выполнение check4.exe в консоли](screen/p7.png)

### Разбор синтаксических ролей:
* **Квадратные скобки `[]`:** Работают как оператор индексации при доступе к элементу массива по смещению (`int val = arr[1];`). Не являются оператором при объявлении размерности статического массива в коде (`int arr[] = {10, 20, 30};`).
* **Круглые скобки `()`:** Выступают оператором при вызове функций (`my_func();`) или при явном приведении типов данных в стиле C (`(int)pi`). Не являются оператором, когда используются для принудительного изменения приоритета математических действий в выражениях (`(5 + 3) * 2`).

## Задание 6. Анализ синтаксической верности комментариев в C++

Все предложенные варианты использования комментариев были проверены путём сборки файла `check6.cpp`.

### Ход тестирования:

Запустил компиляцию файла. Компилятор GCC ожидаемо прервал трансляцию, выдав лог синтаксических ошибок из-за неверной вложенности маркеров.
![Ошибки компиляции check6.cpp в консоли](screen/p9.png)

### Разбор примеров:
1. `cout << "Hello /* комментарий */ world";` — **Верно.** Маркеры находятся внутри строкового литерала и воспринимаются лексером как обычный текст.
2. `// /* \n Это комментарий \n */` — **Неверно.** Знак `//` комментирует всю первую строку вместе с открывающим `/*`. Текст на новой строке лексер пытается разобрать как инструкции кода, ломая сборку.
3. `/* текст /* комментарий */ */` — **Неверно.** В C++ запрещены вложенные многострочные комментарии. Первый же встреченный знак `*/` закрывает весь блок, оставляя финальный хвост вне комментария.
4. `// текст /* комментарий */` — **Верно.** Знак `//` в начале строки заставляет компилятор полностью проигнорировать всё содержимое до конца строки.
5. `/* текст // текст */ \n */` — **Неверно.** Знак `//` внутри блока игнорируется. Первый маркер `*/` завершает блочный комментарий, а одинокий `*/` на новой строке вызывает синтаксический сбой.

![Успешная компиляция check7.cpp в Far](screen/p10.png)

### Синтаксические правила из стандарта C++17:
1. `while ( condition ) statement` — Цикл с предусловием (while). Выполняет тело, пока условие истинно.
2. `do statement while ( expression ) ;` — Цикл с постусловием (do-while). Гарантирует хотя бы один проход тела до проверки условия.
3. `for ( init-statement condition_opt ; expression_opt ) statement` — Традиционный итерационный цикл for со счётчиком, условием и шагом.
4. `for ( for-range-declaration : for-range-initializer ) statement` — Диапазонный цикл (range-based for) для последовательного обхода коллекций.
